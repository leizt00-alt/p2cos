p2cos 每日09:15/10:15恢复巡检任务 v6（Asia/Shanghai，同一个自动任务每天两次）

本任务仅恢复真实上海当天已有的 scheduled run 原 job，不创建 run、不挑选新图、不借用其他历史任务，不改变08:00准备/10:00发布两个原任务的时间。先读取私有 workflow.json、RUNBOOK.txt、RECOVERY.md、QUALITY_TASKS.txt、generation_prompt.txt、SOCIAL_AUTO_UPLOAD.md 和本地代码实际接口。所有实质阶段用全新 spawn_agent(fork_turns="none")，主管仅调度、聚合证据。正常客户端内部使用已有授权；禁止读取/输出/导出凭据、环境变量值、Cookie、Token或浏览器存储，禁止迁移其他会话的授权。恢复非凭据备份不代表登录有效。

1. 用真实时钟确定 Asia/Shanghai 当天，执行 python /workspace/p2cos/p2cos_watchdog.py --config /workspace/p2cos/workflow.json 。它默认只读当天 scheduled:YYYY-MM-DD；保存真实健康输出。禁止先 ensure-scheduled/create-manual/State 初始化做诊断。库、run或job缺失则报告原08任务未形成可恢复job，结束；不能选“最新job”或替换作品。显式 --run-id 只用于定位同一天这个scheduled run，不能自动恢复昨日/手动run。核对输出run_id/job_id/artwork_id与持久记录；缺映射则停止，不按日期猜旧库关联。
2. 已发布或 verified 的任务仅跳过再次生成/发布，仍检查并由全新 fork_turns="none" 存储 agent 补齐全部候选、正式 QA/选择、已验真发布回执及索引；归档同步完整才结束，绝不再次提交。publication unknown/in_flight/reconciliation_required/审核中或可能已提交，交全新独立agent remote reconcile同一提交；不因一页列表没看到就推断未提交，不重置pending、不fallback、不重新点击。只有真正核实的完整远端/UI回执可按既有State入口完成记录。年龄/无心跳本身从来不是失败、未提交、executor已停或远端已停的证据。
3. 准备未完成则只恢复原job，完整任务包包含raw/全部现存版本/实际trace/hash/独立QA/失败项/固定anchor/研究来源/真实journal与回执路径，执行者必须看实际图片。对同job执行 p2cos_recovery.py --db 实际状态库 --job-id 已核实job，核对具体attempt。result_saved验证原结果后只commit，无新调用；recorded派全新独立QA。普通reserved/prepared只有从未dispatch_claimed且原执行者不可用才可审计reassign给全新生成者，保持attempt/预算；已授权replacement不能reassign，只能恢复授权绑定执行者或报告阻碍。
4. unknown/dispatching/submitted先尽力找回真实原结果或续接真实仍有效的cell。尚活跃的新调用继续原等待流程，不能因为09:15/10:15或短阈值而并发替换。只有真实权威观察证明原本地executor已停止，且原调用无法续接，并核验私有workflow配置中的enabled policy和实际explicit_user_authorization及hash、每页独立unknown replacement预算未使用，才能自动有界恢复；同范围已有授权不再逐次询问用户。仅失联、查无活动记录、无法续接本身均不证明已停止；必须有工具权威确认executor不存在/已结束等实际停止依据。记录真实停止工具观察并按RECOVERY.md生成绑定run/artwork/job/page/attempt/generator/dispatch的executor_stopped证据，说明仅本地事实、远端仍unknown。可将artifact引用写入私有executor_stop_evidence数组，用 --evidence-manifest 路径重跑watchdog；仅健康建议本身不授权调用。
5. 由真正全新生成者与真实调度者使用State.supersede_unknown_with_authorization(...,mode="explicit_policy",policy={path,sha256},authorization={path,sha256})原子预留一次replacement。授权封套、停止证据与真实用户policy必须绑定一致，optimization完整继承原attempt保存的对象，包括changes，且仍对应当前最新已记录独立QA及全部未解决项；不能自行重建changes或改写对象来代替原优化槽。保留superseded_unknown原记录，正常优化槽仍最多2，unknown replacement每页最多1，最多4次潜在工具调用。缺任何证据、额外预算已占用或旧结果可恢复，均不追加调用。reserved后仍须prepare→仅首次成功claim→按冻结公开参数真实image_gen→同执行链立即保存真实输出/回执/trace→save→commit→全新独立QA。不得伪造生成成功/失败或未公开型号/工具参数。晚到原结果按audit_late_superseded_result审计保留，不能覆盖replacement或破坏去重。
6. 质量仍保留正常两次优化、全版本独立QA、标准通过优先和耗尽后全新独立择优。unknown/abandoned/superseded_unknown不算有效失败或完成槽；State核验对应槽的真实输出/有效独立QA或真实终结失败。不得清零次数、发半套、把旧较差图未经资格提前降级、跳过全图hash/trace/角色/研究/文案/AI声明/账号/登录/run授权等硬门禁。
7. 09:15入口只完成准备和归档，绝不发布，即使执行跨过10:00也不把这一轮改为发布任务。10:15入口只有真实上海10:00已到才允许继续原publish_task.txt全流程：State.publish_ready实际ready，social-auto-upload dry-run通过，由其publish内部唯一claim并使用冻结包；外层不重复claim。主工具明确未提交失败且有持久证据时才按原fallback-preflight→claim-legacy官方UI回退，全新执行者、同job/稳定去重键、相同门禁。未知结果始终reconcile，不能两种方式循环提交。若触发来源无法确认09:15/10:15，保守按只准备处理，并报告无法确定恢复轮次。
8. 每步保存真实receipt/hash，用SQLite backup API一致性快照及既有私有Drive白名单保存全部候选、QA/选择、journal/trace/停止/授权证据。允许备份recovery_policy.json和recovery_authorization.json等非凭据事实文件，禁止公共Git与任何凭据/profile归档。报告run/job/stage/age/next_action/needs_attention、真实恢复动作、正常/额外预算、QA结论/残差及发布实际状态；缺job也明确报告。继续pending必须说明所缺具体证据和下一步，不能仅写“等待”。

部署说明：本地文件不创建云任务。部署者将本模板全文用于唯一巡检automation，Asia/Shanghai单一日程覆盖09:15和10:15，回读确认prompt版本/时区/两时刻/启用状态，并记录真实ID。执行开始即记录由实际触发时间/调度上下文判定的轮次；只读CLI显示的publish_preflight不是发布授权。原08/10两个任务继续使用v6准备/发布模板，不修改其原时刻。

v6 全部真实成品归档与发布标注（08/10/恢复入口共同规则）
用户已要求每次生图结果都存入 Google Drive，并明确第几次生成、最终选中哪张及是否真正发布；此规则覆盖旧“通过后才创建或上传整个 Drive 作品目录”的限制，仅提前候选与原图归档，不放宽最终成品或发布门禁。
每个版本真实返回、完整解码及 hash 验证通过并经 record_cos（或 save_result→commit 等价入口）落库为 recorded 后，立即派全新 spawn_agent(fork_turns="none") 存储 agent 归档；恢复遇 recorded 也先检查并补齐该版本归档，同时交另一全新独立 QA。不得等待 State.publish_ready 或 QA 通过才保存，不漏存或覆盖低分/落选版本。QA 尚未完成时真实 score=null、qa_status=pending，之后据正式报告幂等更新；存储失败保留本地成果与具体错误，按同版本重试归档，不重新生成来补存。
每作查重并复用唯一 Drive 目录。根目录保存全部 raw；每个真实版本及其实际 prompt、references（引用文件的真实 Drive file ID、角色、页码与 SHA256）、generation trace、工具 receipt、QA/score 和 STATUS.txt 放入 candidates/p{page}/v{physical_attempt}/。先归档引用文件，再记录可回读的实际 file ID；不得用路径/文件名冒充 ID 或 hash。目录与图文件支持 description 时同步说明；不支持则使用该目录 STATUS.txt、manifest.json 和根《生成记录与发布状态.txt》承载完整说明。
根《生成记录与发布状态.txt》与 manifest.json 列全量尝试和真实版本：attempt_number=physical_attempt+1 是“尝试序号”，confirmed_generation_number 是同一作品按真实 recorded 顺序稳定分配并持久保存的“确认成功生成序号”，均同时标明 page、physical_attempt、版本、hash 和 Drive file ID；重复归档、QA完成或选择变化不重编号，不从最大 attempt 推算成功次数。legacy_unknown、unknown、superseded_unknown、failed 等无可验证图片的尝试单列真实证据，成功序号=null、generated=false，明确“无确认成品/结果未知或真实失败”，不得造图、造成功或补猜序号。无法核验历史顺序就保留 unknown 并说明依据缺失。
每个版本明确 generated、selected、published 三个独立 boolean，并记录各自依据、真实分数或 pending；uploaded、queued、reviewing、selected 都不等于 published。图列表名称应可直接辨认，如“成品01_尝试01_候选_{id}_p{page}_cos_v{physical_attempt}.ext”，选中后改“最终选中_待发布”，独立验真后才改“最终选中_已验证发布”；更名复用同一 file ID、保持字节不变，以 file ID+hash 而非可变名称作幂等键。若选择改变，清除旧 selected，保留旧版本及其 published 历史，并如实标注历史已发布状态。
只有全部原门禁通过：完整页组、标准独立 QA 或合法耗尽择优、全图/trace/hash、角色研究与文案、账号/登录、真实 run 授权及对应时间、AI 标识与去重，且 State.publish_ready.ready=true，才可在作品根目录放入仅最终选中整套 {id}_p{page}_cos.ext，与同页 raw 配对；根 cos 字节/hash 必须等于对应 selected candidate，索引明确最终对应第几次确认成品和哪次尝试。候选提前归档绝不是最终选择、质量通过或发布授权。
仅在全新独立核验 agent 已按既有规则验证发布完成并形成真实回执后，才能给实际提交的选定版本 published=true；将真实 post URL/ID（严格 UI 回执无法取得 ID 时保持 null）、验证时间、回执截图/文件 ID 与所选版本 hash/页序绑定。可能已提交、审核中或结果未知保留真实状态并只 reconcile 同一提交，不重复发布。已发布或 verified 的任务仅跳过再次生成/发布，仍检查并由全新 fork_turns="none" 存储 agent 补齐全部候选、正式 QA/选择、已验真发布回执及索引；归档同步完整才结束，绝不再次提交。每次候选归档、QA、选择或发布状态变化后，同步幂等更新人可读索引、manifest、STATUS/可用 description 和列表名称，回读实际目录、文件 ID、名称与可验证内容 hash；相同版本 hash 不符则报冲突而不覆盖；新的生成尝试必须使用其对应新版本目录，同版本归档重试复用原目录和实际文件 ID。此归档规则不改变两次正常优化、一次独立授权 unknown replacement、原 executor 停止证据、独立 QA、social-auto-upload 主方式或仅确认提交前失败才允许的原网页回退职责。
